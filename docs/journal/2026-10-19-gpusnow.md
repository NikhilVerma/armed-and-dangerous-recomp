# 2026-10-19: GPU snowfall in the remaster engine (agent-gpusnow)

Done: the old D3D9-hook remaster's Vulkan snowfall (src/rhi/vulkan/vk_snow.cpp, hook/enhance/weather.cpp) ported to
Bevy as engine/src/graphics/snow.rs + snow.wesl (player feedback FX4: "the newer GPU snow effects" were missing).
Same maths, constants and defaults (1.5 M flakes, volume 150 / sky 70 / below 40, fall 1.6, wind (0.9, 0.35),
turbulence 0.6, drag 0.5, size 0.02, opacity 0.7, streak 4 x 1/120 s). Compute pass + instanced draw after TAA, soft
against the depth prepass, lit and fogged by the level, stopped while paused. Cylinders fxo_snow / fxo_snow_2 hidden
while it snows. Settings block `SnowSettings` (flattened: snow, snow_amount, snow_tuning); Remaster on, Original off;
"GPU Snow" and "Snow Amount" on Graphics > Detail and Shadows. Merged wip/full-decomp (ddfd67a).

Tests: gpu_snow (12 pass), gpu_snow_original (7), fx_snow (12), fx_particles (12), launch_newgame (38),
launch_options (25), geom_menu (35 of 36: its `window.graphics.tessellation` expect fails on wip too, with
target-wt-port-display; not from this branch). Added gpu_snow / gpu_snow_original to tools/regress.py SUITE.

Bench (4K Remaster, --bench 20, background, machine quiet): snow off 115.7 / 116.8 fps avg (1 % low 80 / 95), on
116.4 / 117.2 (87 / 98): at the driver's ~119 cap either way. --profile: snow_draw 0.83 ms, snow_simulate 0.09 ms GPU.
Default amount kept at 1.5 M.

Learned: (1) a shader embedded with `embedded_asset!` is not reliably rebuilt when only the .wesl changes; touch the
.rs and check the exe for the new text. (2) In Bevy 0.20 a pipeline is compiled in the background: do one-time GPU
work (the volume fill) only once `PipelineCache` returns the pipeline, or it is lost.

Open: the human's eye on density / look; the camera's own flake emitter (fxo_glow_red) still runs alongside (the old
hook muted it; FX1 wanted its flakes) - mute it if the two together read as too much.
