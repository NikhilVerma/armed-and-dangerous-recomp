# 2026-10-24: macOS readiness (branch macos-ready)

The maintainer will be on a Mac for two weeks and builds there themselves; this pass makes the engine and its asset
tools build and run on macOS without a roadblock, proven by CI (no Mac here). Write-up for players: docs/macos.md.

## Done

- `engine/src/platform/` (new): the one place for system differences. `app_data_dir` (the `dirs` crate:
  %LOCALAPPDATA%\AndRemaster, ~/Library/Application Support/AndRemaster, XDG), `user_files_dir` (options.json and
  saves/ next to the executable, as before), `find_system_font` (Windows Fonts; macOS Supplemental/Arial.ttf, any
  case), `utc_offset_secs` (Windows FileTimeToLocalFileTime moved here from saveslots.rs; unix localtime_r), and the
  pointer policy `PLAY_POINTER`.
- Pointer on macOS: winit has no `Confined` there (it falls back to None) and `set_cursor_position` warps and
  re-associates the cursor, holding back mouse events after each warp. So macOS locks the pointer in play while
  focused (released without the focus: a lock is system-wide), never warps it, and the look reads raw motion
  (winit macOS emits DeviceEvent::MouseMotion). Windows behaviour unchanged (cursor.rs `grab_with` tests both).
- Session folders now use the local time on every system (was UTC off Windows); the session root comes from
  `app_data_dir` (same folder as before on Windows).
- Case: exports are all lower case (checked: no upper-case file name in any work/remaster level folder);
  `texture_path` lower-cases the original texture path too, and the level asset reader retries a missed path in
  lower case. Tools: `gamefiles.find_ignoring_case` for the streamed sounds' bank paths, `.pcv` matched in any case.
- `graphics/bc_decode.rs`: a DDS loader that decodes BC1-3 to RGBA8, registered only when the adapter lacks
  TEXTURE_COMPRESSION_BC (or `AND_DECODE_BC=1`). Every Mac has BC under wgpu Metal (wgpu-hal: `format_bc` is true
  on macOS), so this is for iOS / Android later; unit-tested block by block.
- `engine/play.sh`; `tools/platform_paths.py` (exe name, app data dir, ffmpeg via PATH / winget / Homebrew, the play
  command) used by setup_assets.py, playtest.py, level_smoke.py, session.py, remaster_export_movies.py.
- CI: `engine-macos` (macos-latest arm64: release build + unit tests), `engine-macos-intel` (cargo check
  --target x86_64-apple-darwin: compiles Jolt's C++ for x86_64 too), `tools-macos` (compile, unit tests,
  setup_assets --check). The Windows jobs are unchanged.

## Learned

- oxijolt-sys lists aarch64/x86_64-apple-darwin in its bindings family "gnu", links libc++ on Apple, and the cmake
  crate sets CMAKE_OSX_ARCHITECTURES per target: Jolt should build with Xcode's clang + Homebrew CMake. No iOS
  target in its bindings (an iOS blocker).
- No wgpu backend is forced anywhere; no shader uses 64-bit atomics, subgroups or push constants; the storage
  texture formats (r16float / r32float / r32uint / rgba16float) are Metal-supported, XeGTAO keeps Bevy's
  USE_R16FLOAT switch.
- The audio device follower is cpal-generic (CoreAudio on macOS); nothing to change.
