# 2026-10-22: accuracy audit wave 2, package g29 (agent-fix2-g29)

Checked the 65 findings of work/audit/wave2/g29.json (engine/src/fxvm/script.rs: the fx interpreter;
engine/src/fxvm/streamers.rs: ribbon trails) against the current code (base 0e5c587). Reachability was checked over
the 24 level fx banks (work/remaster/*/fx.json, 965 scripts). A first run of this package was paused with its work
uncommitted in another worktree; this run carried that work over, dropped its 0x64 change (agent-fix2-g25 already
reworks fx gravity: `make_dynamic` takes the object's own scale and 0x11 re-makes a falling body) and finished the rest.

Files outside the package: engine/src/fxvm/object.rs (the `Facing` modes replace the `kite` flag; one comment on the
exp scale), docs/engine-limits.md (row R13, the streamer ring), docs/original-bugs.md (the NaN exp scale),
engine/playtests/fx_streamer_pause.json (new).

Key evidence that settled many items: 0x00407ff0, which every "error message" finding cites (FxPushError ->
ConsolePrint, "Too many emitters", "Failed to find streamer texture", "need streamer"), is the game's debug log
compiled out to a bare `ret` (render_r2b.cpp:163). The shipped game prints none of these, so those claims are false.

## Player-visible changes

- Streamers stop while the game is paused (0x00494f30): the trail no longer collapses to a stub under the pause menu.
- Streamer trails are as long at 144 / 240 Hz as at 60 Hz (0x004958a0): the original's 63-point ring is kept as a time
  span (62 frames at 60 Hz, `RING_SPAN`); at 144 Hz the trail used to reach back only 0.43 s.
- The oldest end of a streamer has its width from the start (0x004959b0: the first point's direction is e2 - e1).
- Overlapping streamers of one texture draw newest first (0x00494fc0).
- The level 3 / level 5 fire animations (fxo_flame_anim, opcode 0x4c) stand upright and turn about the vertical to
  face the camera (0x00419a60 bit 0x4000000); they kept their spawn rotation before.
- Objects attached by 0x13 are inert (0x00423680: +0x424 |= 0x20000): the monk's third ball lightning
  (fx_ball_lightning, 0x1a spin) stays on him instead of becoming a free body.
- A running or paused fx whose parent object has ended (or whose owner entity is gone) ends at its next step without
  making anything more (Fx_RunScript 0x00420770 entry check), as waiting ones already did.
