# 2026-10-22: accuracy audit, group "world" (agent-fix-world)

Checked the 16 findings of work/audit/fix-pilot-world.json against the current code (base wip/full-decomp 1c265b9).

## Fixed

- Movable objects (0x004505a0 / 0x00450af0, engine/src/movable.rs):
  - the damage record now carries the mover's normalised velocity and direct_damage_force; Roman's handler knocks him
    back with it (Roman::knock, PlayerObject_OnHit 0x0047afa0). The AI (0x00430340) and object (0x00450da0) handlers
    do not read +0x24. In the shipped data no movable reaches a living Roman with it: every damaging movable has
    crush 1 (crush clears on_hit_damage at load), and a crush takes his whole health.
  - a dead mover (health <= 0, the original's 0x80) skips the roll loop, the landscape fx and the records, as the
    update returns early; on_hit_death now kills before those (its contact's fx no longer fire, as in the original).
  - on_hit_fx and fx_boulder_impact start at the contact point (contacts.rs Touch.point, the mean of Jolt's manifold
    points), not the mover's centre: on_hit_fx at the step's first landscape contact, the impact at the last.
- Fx meshes (0x004897d0, fxvm): the record's opacity (+0x48) is now applied to additive (blend 0) records and the
  layered snow domes as well, as the constant alpha the draw state sets whatever the blend (alphaOp with 0x40000 takes
  the texture factor: auto_00506210.cpp). Visible: fxo_glow_red 0.1, fxo_trail_bullet 0.15, the shorelines, rain,
  ripples and lanterns 0.25..0.8, the snow domes 0.8 now draw at that share. Worth a look in play.
- engine/src/ai/launch.rs: Game+0xb34 is set by MissionObject_Load 0x0044c170, not 0x0045a4e0 (citation).

## Checked, no change

- Roll-loop threshold [0x005bce84] = 16.0, crush cosine [0x005bce80] = -0.2, impact speed [0x005bce7c] = -50.0, read
  from game.unpacked.exe: the engine's literals match (docs/subsystems/objects.md said -0.65: corrected).
- The impact flag 0x40000: the contact callback runs once per step and contact (contacts.rs), so the original re-sets
  it every step a contact sees v.z < -50, as the engine does: no latch to add.
- death_timeout: only p_shootable_health / _token / _turret_upgrade set it (20), the drops icobject.rs handles.
- vt+0xfc(1, 2) per frame: the nav-grid mark (DefaultGameObject_MarkGrid 0x004509a0), replaced by nav.rs (port/ai.csv).
- 0x004897d0 blend byte for world meshes: over all exported models the kind-0x10 records are blend 2 (191) or blend
  0 (55, all fxo_ models, drawn by the fx path, which honours it); no blend 1, no other value, no mode-2 record at
  opacity 1, no non-0x10 record with opacity < 1.
- Backgrounds (0x0040a890): every level's background objects use p_background (sorting_order 1, fog 0) and each
  template has one LOD model, so (guess: the loop's info+0x24 x +0x28 counts those models) the fog-slot bug
  (docs/original-bugs.md) never sets the bit; equal sorting orders leave nothing for the key to order.
