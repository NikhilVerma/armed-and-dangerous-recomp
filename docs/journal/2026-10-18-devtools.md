# 2026-10-18: developer menu and session recording (agent-devtools)

Branch `agent-devtools` from wip/full-decomp e26cdae; build dir engine/target-wt-devtools. For the human's end-to-end
play: a developer menu, hotkeys, command-line setups, and a recording of each play session with bookmarks, so bulk
feedback can point at exact moments.

## Done

- engine/src/devtools/mod.rs: `DevSettings` (options.json "dev"), `DevToggle` (god mode, invincible, infinite ammo,
  big heads / hands / boots, topsy turvy screen, unlock all levels and movies: the cheat flags of cheats.rs, now named
  constants there; FPS and state overlays), `DevAction` (full health, full ammo, every special + gun slots filled,
  quick save F5, quick load F9, restart level, bookmark F8), `DevCommand`, `DevOverlay` (pause under a developer
  screen, the game's menus take no input meanwhile), command line `--level LEV` (New Game setup in that level) and
  `--dev god,infammo,...`. cheats.rs: `full_ammo` / `full_health` shared by the codes and the menu.
- menu.rs: the egui menu, F1 / pad View + Y / a "Developer menu (F1)" button under the title and pause menus. Pages: Main,
  Levels (every exported campaign and bonus level, "Name  (lev_id)"), Weapons (any gun into Roman's hands: he carries
  three, so "give every weapon" fills the free slots and the page swaps the rest in). Mouse / trackpad clicks, keys
  and pad through input::Controls. Level select reuses the Extras replay start (campaign::new_game, RestartTo::Level)
  with replay mode off, so the campaign continues after a win.
- overlay.rs: FPS / frame ms and a state panel (level, mission, goal, Roman's game position, health, weapon, special);
  egui zoom by window height (the window runs at scale factor 1, so egui was tiny at 4K).
- session.rs: the session folder per launch (`%LOCALAPPDATA%/AndRemaster/sessions/<local time>`): game.log via a
  tracing layer in the LogPlugin, events.jsonl (the existing EVENT lines plus level started, Roman died, mission
  won / failed, dev toggles / actions, bookmarks, slow frames), state.jsonl (PlayState at 2 Hz, bulky lists every 10
  s), inputs.jsonl (per frame with input), frames.jsonl (5 s stats), panic.txt with backtrace, bookmarks (F8:
  screenshot, a save at that moment, optional typed note). Retention 20 sessions / 2 GiB, only session-named folders.
- tools/session.py (list / show / repro) and tools/test_session.py; regress.py SUITE: devmenu_toggles, devmenu_level,
  devmenu_title, devtools_quicksave, devtools_bookmark, pyunit (new runner case for tools/test_*.py).
- docs/play-guide.md: the menu, toggles, hotkeys, command line, bookmarks, where sessions are, feedback by bookmark.

## Performance

4K Remaster bench (`--bench 20 --size 3840x2160 --background --preset remaster`, alternated, the dev-tools build
recording a session through AND_SESSION_DIR): before 117.3 / 117.1 / 117.1 fps (1 % low 61 / 95 / 98, p99 9.8 / 10.0 /
10.1 ms), after 117.2 / 117.3 fps (1 % low 91 / 97, p99 10.0 / 10.0 ms). Both at the driver's ~119 Hz cap. State line
sizes on lev_1_m1: ~9 KB slim, ~24 KB full, so about 75 MB an hour of play in state.jsonl.

## Learned

- `PlayState` is built every frame in normal play too (it always was): the session only serialises it twice a
  second. Its "events" list was never drained outside scripts (it grew all session); the session now drains it.
- Bevy 0.20's LogPlugin takes a `custom_layer` fn pointer: the session's files sit in a static set before the app is
  built.
