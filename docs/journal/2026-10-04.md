# 2026-10-04

Goal: docs/goals/modern-renderer.md (renderer recovered, our interface, Vulkan backend at parity).

## Done

- Step 1, renderer core:
  - All 295 functions in 0x004fb000-0x0050d000 are at S2, recovered by two parallel batches.
  - Ghidra had missed 1,288 functions reached only through vtables and callbacks. `tools/gh.py define` added
    them; the tracker now has 5,520 functions.
  - ABI-scanner fixes:
    - EBP inputs are supported.
    - Tail calls take the target's `ret`; no-return functions are marked.
    - ST0 returns need evidence in the callee.
    - Caller-cleaned stack arguments get a lower bound from the callee's own stack reads.
    - `mov r, r` padding is neither a read nor a write.
  - A bisect found the 0x44-byte game-matrix trap (rule added to the recovery guide).
- New comparison scenarios:
  - reset: a lost device at frame 600
  - play: mouse and keys dismiss the briefing, fire, pause and resume
  - quit: WM_CLOSE, the game's own shutdown, with the final partial frame traced
- `tools/coverage.py` counts calls per function: 212 of 291 renderer functions run in the scenarios.
- Step 2, interface:
  - The D3D9 COM facade (generated from d3d9.h) feeds `rhi::` (73 operations, src/rhi/rhi.h).
  - The D3D9 backend is a pass-through. All 5 scenarios are identical and no method falls back outside the
    interface.
  - Loading frames are marked "L" in the trace: async streaming varies their uploads, even in the original.
  - docs/renderer-interface.md written.
- Decisions:
  - Vulkan, with sources fetched by CMake.
  - Our own backend rather than DXVK, because ray tracing, path tracing and PBR need control of geometry and
    materials.
- docs/goals/remaster-basics.md holds the human's list: aspect ratio and UI, menu extension, persistent decals
  and bodies, FOV, tessellation, QoL.

## In progress: Vulkan backend (step 3)

- Dependencies: Vulkan-Headers, volk (header-only, compiled in vk_context.cpp) and glslang, all at
  vulkan-sdk-1.3.296.0.
- Core (written here):
  - vk_context: instance and device, formats.
  - vk_resources: images, surfaces, textures with CPU copies, renamed buffers, shaders.
  - vk_device: frames and swapchain, dynamic rendering, D3D9 state shadow, the draw path, and frame dumps for
    the parity test.
  - The adapter queries a real IDirect3D9, so caps (and so the game's rendering paths) are identical.
- Agent modules:
  - vk_shader_translate: vs_1_1 / ps_1_1 to GLSL. The corpus is work/shaders: 228 vs, 3 ps, from
    `[test] dump_shaders`.
  - vk_fixed_function: FF vertex and pixel shaders, plus D3D9_FINAL (fog and alpha test).
  - vk_pipeline / vk_pipeline_input: render states to pipelines, vertex input, samplers.
- Offline test: `vk_shader_test` (`build.ps1 -Target vk_shader_test`).
- Parity: `tools/compare_backends.py` compares draw counts per frame (`[test] rhi_draws`) and frame images by MAE
  and the share of bad pixels.

## Risks and notes

- DLSS/DLAA runtimes are 64-bit only and the game is 32-bit. DLAA will need a 64-bit build of the recompiled
  game or an out-of-process renderer.
